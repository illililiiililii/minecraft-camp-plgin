# CampfireCoop — 모닥불 원정대

Minecraft Java **Paper 1.21.11 / Java 21 이상**에서 사용하는 3~4인 협동 생존 플러그인입니다.

## 플레이 기능

- **공동 목표 8단계:** 원목 128 → 철 주괴 64 → 몬스터 40 → 농작물 128 → 블레이즈 막대 12 → 다이아 16 → 위더 → 엔더 드래곤. 단계별 개인 보상과 미수령 내역을 저장합니다.
- **황당한 원정 3종:** 닭 부장의 야근 던전, 감자 왕국 세무조사, 우주 출장 해골. 2명 이상이 48블록 안의 공터에 모이면 3차 전투에 도전할 수 있습니다. 닭 감사팀·몬스터 공중 부양·감자 속보가 끼어듭니다.
- **누적 하늘 택배:** 서버 전체에서 최초 1분, 이후 기본 2분마다 접속한 일반 월드 생존자 한 명에게 적립합니다. 지하에서도 쌓이고, 지상으로 나오면 1초마다 하나씩 떨어집니다. 동시에 3개까지만 내려오며 본인이 주워야 수령 완료됩니다. 미수령 택배는 재접속·정상 재시작 후에도 유지됩니다.
- **제한 장비:** 날카로움 VII 나무검(32타), 날카로움 V 철검(24타), 보호 VI 철 흉갑(피해 24회), 희귀 날카로움 VII 철검(12타). 효율 VI 다이아 곡괭이·도끼·삽·괭이·가위는 채굴 96회 제한입니다. 수리·합성·추가 인챈트를 제한합니다.
- **현상수배 정예몹:** 자연 생성 몬스터 중 드물게 강화된 이름표 몹이 등장합니다. 한 번에 한 마리, 5분 제한, 최소 3분 간격. 근처 기여자에게 에메랄드 1개와 경험치 50, 마지막 처치자에게 다이아 1개를 추가 지급합니다.
- **파티 콤보:** 친구와 15초 안에 번갈아 자연 몬스터를 처치하세요. 5연속마다 신속 10초·재생 6초·경험치 25를 받으며 보상은 60초 간격입니다. 같은 사람의 연속 처치, 시간 초과, 48블록 이상 이동은 연속 기록을 새로 시작합니다. 스포너·원정 몹은 제외합니다.
- **수상한 낚시:** 낚시 성공 시 20% 확률로 보너스가 등장합니다. 에메랄드·수상한 감자·엔더 진주·희귀 다이아 또는 우스운 사직서가 택배함에 적립됩니다. 개인 재사용 90초, 원래 낚시 보상은 유지합니다.
- **사망 회수 상자:** 장비·인벤토리를 한 상자 모양의 전용 보관함에 저장합니다. 내용이 많으면 여러 페이지로 표시하며, 본인과 운영자만 좌표 8블록 안에서 회수할 수 있습니다. 인벤토리가 부족하면 나머지를 보관합니다. 경험치와 소멸 저주 등 드롭 제외 규칙은 기본 게임 규칙을 따릅니다.
- **편의 기능:** 웅크려 도끼 벌목(최대 64원목), 웅크려 성숙 작물 우클릭 수확·재심기, 인벤토리 정리, 휴대용 제작대, 엔더 상자를 지니고 여는 원격 창고, 상대가 수락하는 친구 이동, 공용 기지 귀환, 1인 수면.
- **UI:** 클릭 메뉴, 공용 목표/전투 보스바, 액션바 HUD, 타이틀·파티클·사운드. 개인별 이펙트 전환을 지원합니다.
- **안내서:** 처음 접속하면 모든 기능을 설명하는 29페이지 책을 지급합니다. 클릭형 목차·명령 버튼이 있고, 사망 시 한 권을 유지하며 `/camp book`으로 다시 받을 수 있습니다.

## 빌드

JDK 21 이상과 Maven 3.9 이상에서:

```powershell
mvn -B -ntp verify
```

산출물은 역할이 다릅니다.

| 파일 | 설치 위치 |
|---|---|
| `target/CampfireCoop-1.7.0-loader.jar` | `server/plugins/CampfireCoop-Loader.jar` |
| `target/CampfireCoop-1.7.0.jar` | `server/plugins/CampfireCoop/runtime.jar` |

로더 JAR만 `plugins` 바로 아래에 넣습니다. 일반 기능 JAR은 `CampfireCoop` 데이터 폴더 안의 `runtime.jar`로 설치하세요. 기존 단일 `CampfireCoop-*.jar`는 서버 종료 후 플러그인 폴더 밖으로 옮기고, 기존 `plugins/CampfireCoop` 데이터는 유지합니다. 최초 로더 전환에는 한 번의 정상 재시작이 필요합니다.

## 서버를 끄지 않는 기능 업데이트

최초 로더 설치 후에는 서버를 켠 채 새 기능 JAR을 스테이징할 수 있습니다.

```powershell
.\Apply-Update.ps1 -ServerPath 'C:\Minecraft\server' -RuntimeJar '.\target\CampfireCoop-1.7.0.jar'
```

스크립트가 `plugins/CampfireCoop/updates/update.jar`를 복사하고 SHA-256 파일을 마지막에 게시합니다. 실행 중인 로더는 5초마다 확인하여 새 모듈을 적용합니다. 운영자의 `/camp update`도 준비된 업데이트를 적용합니다.

로더는 기존 리스너와 예약 작업을 정리하고 별도 클래스 로더에서 새 코드를 시작합니다. 적용 전 YAML 상태를 `updates/backups`에 보관하고, 새 모듈 활성화가 예외로 실패하면 이전 모듈과 저장본을 다시 불러옵니다. 결과는 `updates/result.properties`에 기록합니다. 정상적인 데이터 호환 업데이트를 대상으로 하며, 향후 데이터 형식 변경에는 별도 마이그레이션 검토가 필요합니다.

**플레이어 접속과 월드는 유지됩니다. 진행 중인 원정과 귀환 준비는 패치 시 종료됩니다.** 아이템·공동 목표·미수령 보상·회수 상자·택배는 저장본을 이어갑니다. `/camp reload`는 같은 모듈을 다시 시작하여 설정을 재적용합니다. 서버 본체, Java 또는 로더 자체 변경에는 정상 재시작이 필요합니다. 이 로더는 CampfireCoop 기능 모듈용입니다.

## 주요 명령어

| 명령어 | 기능 |
|---|---|
| `/camp` | 클릭형 원정 본부 |
| `/camp status`, `/camp donate`, `/camp reward` | 목표·납품·보상 |
| `/camp book` | 안내서 재지급 |
| `/camp adventure [start]` | 원정 현황·출발 |
| `/camp fun` | 현상수배 현황·추가 놀이 규칙 |
| `/camp graves` | 내 사망 회수 상자 좌표 |
| `/camp home` | 공용 기지로 이동 준비 |
| `/camp utils` | 편의 메뉴 |
| `/camp tree`, `/camp sort`, `/camp craft`, `/camp ender` | 벌목·정리·제작·엔더 창고 |
| `/camp tpa 닉네임`, `/camp tpaccept`, `/camp tpdeny` | 친구 이동 요청·수락·거절 |
| `/camp effects` | 이번 접속 동안 개인 연출 전환 |
| `/camp version` | 실행 중 모듈 버전 |
| `/camp sethome` | 운영자: 공용 기지 지정 |
| `/camp adventure cancel` | 운영자: 원정 취소 |
| `/camp update`, `/camp reload` | 운영자: 모듈 패치·설정 재적용 |

`/coop`도 `/camp`와 같습니다. 이동은 기본 8초 준비, 피해 후 10초 제한, 이동/피해 시 취소, 성공 후 60초 재사용을 적용합니다. 친구 이동은 30초 안에 상대의 수락이 필요합니다.

## 저장과 설정

설정은 `plugins/CampfireCoop/config.yml`에 생성됩니다. `presentation`, `convenience`, `fun`, `sky-supply` 항목으로 기능을 조정합니다. 원정/택배의 시간과 도구 횟수에는 코드상 범위를 적용합니다.

`state.yml`은 목표·기지·보상, `graves.yml`은 사망 아이템, `supplies.yml`은 미수령 택배, `fun.yml`은 현상수배·추가 보상 재사용 기록을 저장합니다. 서버를 `stop`으로 완전히 종료하고 월드·플레이어·플러그인 데이터가 들어 있는 서버 폴더 전체를 함께 백업/복원하세요. 정전 순간의 플레이어 저장과 원장 사이 원자성까지 보장하지는 않습니다.

## 검증

현재 자동 테스트 **59개**, 실패·오류·건너뜀 0. 실제 Paper 1.21.11에서 시작, 모듈 교체와 의도적 활성화 실패 후 이전 모듈 복구를 확인했습니다. 테스트 서버의 프로세스 ID와 포트는 교체 중 유지됐습니다. 모든 전투·낚시·클라이언트 화면 조합을 직접 실플레이 검수한 것은 아닙니다.

GitHub Actions는 Java 21에서 빌드·테스트하고 로더/기능 JAR을 아티팩트로 제공합니다. 저장소에는 서버 본체, 월드, 플레이어 데이터, 운영 서버 설정과 로그를 포함하지 않습니다.
